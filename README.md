# rsna-pe-ct

Pulmonary embolism (PE) detection on CT pulmonary angiograms by adapting a pretrained 3D CT
foundation model ([SPECTRE](https://huggingface.co/cclaess/SPECTRE-Large)): the ViT backbone
runs frozen once per study, then its feature combiner (LoRA or last blocks) plus an MLP head
are fine-tuned with group-stratified cross-validation.

Dataset: RSNA-STR Pulmonary Embolism CT (RSPECT), read in place from the Kaggle competition
mount. Compute: Kaggle GPU notebooks. The owner is an ML/CV engineer with no medical
background; every notebook explains the medical terms it uses in ML language and every plot is
preceded by what you are looking at, why it matters and what to look for.

## The two notebooks (Kaggle)

| Notebook | What it does | Runtime |
|---|---|---|
| `notebooks/01_eda.ipynb` | labels, frozen splits, what scans and clots look like, where clots sit | CPU, minutes |
| `notebooks/02_finetune.ipynb` | frozen backbone once (cached descriptors), fine-tune combiner + MLP, 5-fold CV, test once | GPU; extraction is the slow part |

Setup on Kaggle, per notebook: Add Input -> Competitions -> RSNA STR Pulmonary Embolism
Detection; Internet on (the first cell clones and installs this repo); GPU for 02. The code
detects Kaggle: DICOMs are read from `/kaggle/input/competitions/rsna-str-pulmonary-embolism-detection/`,
outputs go to `/kaggle/working/rsna-pe/`, scratch to `/tmp`. Nothing is copied or archived.
Labels and the seeded splits are rebuilt by whichever notebook runs first, so the two are
independent. Subset sizes live in `pe_ct/config.py` (`n_dev`, `n_test_sample`, `n_eda`) and can be
overridden in a notebook's CONFIG cell.

`notebooks/legacy_colab/` holds the earlier six-notebook Colab/Drive series (S3 streaming,
tar shards, linear probe, heatmaps); it still works but is not the current workflow.

## Layout

```
pe_ct/                 importable package (all logic lives here)
  config.py            paths (Kaggle / Colab / local), seeds, subset sizes, HU constants
  colab.py             session report, Kaggle input symlinks, Drive mount
  io.py                zip index + range-request downloads (S3 source only)
  labels.py            train.csv -> one row per study, groups, binary target, slice-label alignment
  splits.py            stratified, leak-free test pool / dev subset / EDA subset / folds
  volume.py            DICOM slices (pydicom) -> LPI-oriented int16 HU volume + meta; header-only reader
  storage.py           shards, atomic writes, failure log, volume stores (shard-backed or live)
  viz.py               windows, slice / orthogonal views, overlays, galleries, confusion matrices
  embed.py             SPECTRE loading, preprocessing, extraction, crop-grid geometry
  finetune.py          LoRA, combiner classifier, training loop, StratifiedGroupKFold CV, ensemble
  probe.py             linear probe, metrics (macro F1 headline), thresholds, bootstrap
  explain.py           crop occlusion heatmaps, z-profiles, z-hit rate
  pipeline.py          per-study read/decode, labels+splits on demand, resumable extraction loops
notebooks/             01_eda, 02_finetune (generated by scripts/build_notebooks.py, outputs cleared)
scripts/nb/            the notebook cell definitions (edit these, then rebuild)
tests/                 pytest, CPU-only; synthetic volumes + an 8-slice real fixture
```

## Data notes (verified against the public bucket, October 2026)

- `train.csv` has 7,279 studies (1,790,594 slice rows), exactly one series per study; 4,911
  negative, 2,211 PE-positive, 157 indeterminate (dropped). Its row order does **not** follow
  slice position, so z-position analyses need assembled volumes.
- All zip members are deflate-compressed; one DICOM slice is about 525 KB raw, 280 KB compressed.
- In a random sample of 40 studies: 70 % Implicit VR Little Endian, 22 % Explicit VR, 8 % JPEG
  Lossless (hence the `pylibjpeg` dependencies); slice thickness 0.625 to 1.25 mm (one 5 mm
  outlier seen), in-plane 0.5 to 0.84 mm; every study axial.
- The `Manufacturer` tag is absent from almost every file, so the vendor-specific reconstruction
  kernel name (`ConvolutionKernel`) is used as the scanner proxy for the shortcut analyses.
- Some studies have missing slices; the stored volume is the stack of existing slices and the
  metadata carries the true per-slice positions plus `n_missing_slices_est`.
- GDCM's series scanner rejects the Implicit-VR files with this dataset's anonymised UIDs, so
  slices are read with pydicom and the geometry is built from the headers.

## Conventions

- Stored volumes are `int16` HU arrays `(z, y, x)` in **LPI** orientation: slice 0 is the top
  of the scan, `imshow(vol[z])` is the standard radiological axial view.
- `meta["slice_labels"][z]` is the `pe_present_on_image` label of slice `z`.
- SPECTRE is fed a RAS-oriented HU tensor; crop boxes are mapped back to `(z, y, x)` indices
  (`boxes_lpi`) so heatmaps overlay the stored volumes exactly.
- Macro F1 is the headline classification metric; accuracy, AUROC and AUPRC are reported alongside.
