# rsna-pe-ct

Pulmonary embolism (PE) detection on CT pulmonary angiograms with a **frozen** 3D CT
foundation model ([SPECTRE](https://huggingface.co/cclaess/SPECTRE-Large)) and a
**linear probe**, followed by an error analysis and crop-level heatmaps.

Dataset: RSNA-STR Pulmonary Embolism CT (RSPECT), read directly from the public AWS
Open Data bucket with HTTP range requests (no Kaggle login, no full download).
Compute: Google Colab (one GPU). Storage: Google Drive. Code: this repo.

The owner is an ML/CV engineer with no medical background; every notebook explains the
medical terms it uses in ML language and every plot is preceded by what you are looking
at, why it matters and what to look for. The full plan is in
[PLAN_rsna_pe_frozen_backbone.md](PLAN_rsna_pe_frozen_backbone.md).

## Layout

```
pe_ct/                 importable package (all logic lives here)
  config.py            Drive paths, bucket URL, seeds, subset sizes, HU constants
  colab.py             session report, Drive mount, free space
  io.py                zip index (central directory) + parallel range-request downloads
  labels.py            train.csv -> one row per study, groups, binary target, slice-label alignment
  splits.py            stratified, leak-free test pool / dev subset / EDA subset / folds
  volume.py            DICOM series -> LPI-oriented int16 HU volume + meta; RAS conversion
  storage.py           marker-gated tar / npz shards, atomic writes, failure log
  viz.py               windows, slice / orthogonal views, overlays, galleries, slice scroller
  embed.py             SPECTRE loading, preprocessing, extraction, crop-grid geometry
  probe.py             linear probe, metrics (macro F1 headline), thresholds, CV, bootstrap
  explain.py           crop occlusion heatmaps, z-profiles, z-hit rate
  pipeline.py          per-study fetch -> volume -> (shard | embed), resumable loops
notebooks/             00 ... 05, generated by scripts/build_notebooks.py (outputs cleared)
scripts/nb/            the notebook cell definitions (edit these, then rebuild)
tests/                 pytest, CPU-only; synthetic volumes + an 8-slice real fixture
```

## Running on Colab

1. Open a notebook from `notebooks/` in Colab (GPU runtime for 03 and 05).
2. Run the first cell: it clones (or fast-forwards) this repo, `pip install -e .`, and mounts Drive.
   Re-running that cell after a `git push` picks up new code without a kernel restart.
3. Run the notebooks in order. Each one is resumable: shards that already carry a
   `.done.json` marker are skipped, failed studies are logged to `results/failures_<nb>.csv`.

| Notebook | What it does | Runtime |
|---|---|---|
| `00_setup_and_splits` | labels, zip index, study table, frozen splits | CPU, ~5 min |
| `01_download_subset` | EDA volumes (HU, head-first) into tar shards on Drive | CPU, hours |
| `02_eda` | labels, scans, what a clot looks like, where clots sit | CPU |
| `03_extract_embeddings` | SPECTRE embeddings for dev + test sample, streaming | GPU, hours |
| `04_linear_probe` | probe, curves, CV, learning curve, sub-types, one test evaluation | CPU/GPU |
| `05_errors_and_heatmaps` | error galleries, occlusion heatmaps, z-hit check | GPU |

Data layout on Drive (`/MyDrive/rsna-pe/`): `labels/`, `splits/`, `volumes_eda/`,
`embeddings/spectre/`, `results/`, `figures/`.

A quick end-to-end check with tiny subset sizes: set the environment variable
`PE_CT_SMOKE=1` before running the CONFIG cell.

## Local development

```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e ".[dev,embed]"
.venv/bin/python -m pytest
.venv/bin/python scripts/build_notebooks.py
```

Tests run on CPU with synthetic data plus a tiny real fixture (see `tests/fixtures/README.md`
for the dataset citation). Code that needs a GPU is written so it also runs on CPU with a tiny
input, so shape and logic bugs are caught locally.

## Conventions

- Stored volumes are `int16` HU arrays `(z, y, x)` in **LPI** orientation: slice 0 is the top
  of the scan, `imshow(vol[z])` is the standard radiological axial view.
- `meta["slice_labels"][z]` is the `pe_present_on_image` label of slice `z`.
- SPECTRE is fed a RAS-oriented HU tensor; crop boxes are mapped back to `(z, y, x)` indices
  (`boxes_lpi`) so heatmaps overlay the stored volumes exactly.
- Macro F1 is the headline classification metric; accuracy, AUROC and AUPRC are reported alongside.
